# 技能创建

## 步骤

1. 澄清需求：该技能解决什么问题、何时触发（写入 description）、输入输出是什么、目标智能体具备哪些工具。信息不足先提问，不要臆造。
2. 查重与复用：用 list_skills 核对既有技能，避免重复造轮子；新技能可复用既有技能的结构模式。需要调用外部服务时用 list_connectors 核对连接器名称与能力，引用名必须逐字一致。
3. 设计结构：
   - frontmatter 仅两个字段：name（小写中划线，见名知义）、description（一句话说明「何时使用」——运行时靠它自动激活，必须具体、含触发场景）；
   - 正文分「## 步骤」与「## 约束」两节：步骤可执行、每步有明确产出；约束防滥用（适用范围、写盘须确认、失败处置）。
4. 向用户展示完整 SKILL.md，确认后用 write_skill 落盘（会弹审批卡）。
5. 验证建议：告知用户把新技能挂到目标智能体后如何触发（直接描述场景自动激活，或 //技能名 显式调用）。

## 约束

- 技能中引用的工具名必须真实存在于目标智能体的工具面（内置工具如 Read/Glob/Grep/Bash，平台工具全名如 mcp__donger-platform__write_skill）；不确定就先问，不写猜测的工具名。
- 一次只创建一个技能；技能内不内嵌凭证、密钥或具体环境路径。
- 用户未确认前不调用 write_skill。
