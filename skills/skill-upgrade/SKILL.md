# 技能升级

## 步骤

1. 定位目标：用 list_skills 确认技能存在（名/pack/描述），再用 read_skill 读取当前 SKILL.md 全文。目标不明确先向用户确认要升级哪个。
2. 收集证据（按可用性取用，不臆造）：
   - 用户的口头反馈与本次诉求；
   - donger-audit 工具可用时：检索该技能相关会话的执行记录（哪些步骤反复失败、哪些工具被拒或不存在）；
   - 工具面变化：技能引用的工具是否已退役或改名。
3. 差距分析：列出「证据 → 问题 → 修订方向」对照表，与用户确认修订范围。
4. 重写 SKILL.md：以 diff 或全文形式展示修改点，每处修订附一句证据理由；引用的工具名逐一核对真实存在。
5. 确认后用 update_skill 落盘（会弹审批卡），汇报改了什么、如何验证。

## 约束

- 只修订证据支持的点，遵循 YAGNI；不做无证据的「顺手优化」。
- 仅可更新发起用户自己名下、来源为 paste/upload 的技能；预装（builtin）与 git 源技能只读——git 源给出上游仓库的修改建议，预装技能向平台管理员反馈。
- 修订不得扩大技能的危险面（新增写盘/外发操作须显式提示用户）。
- 用户未确认前不调用 update_skill。
